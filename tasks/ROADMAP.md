# Черга завдань української бібліотеки

Це **дорожня карта пріоритетів**, а не автоматично оновлювана статистика GitHub. Перед новим CLAIM перевірте [відкриті Issues](https://github.com/juv4uk/ukrainian-books/issues), [відкриті PR](https://github.com/juv4uk/ukrainian-books/pulls), їхні змінені файли та коментарі. Старий замір нижче залишено для відтворюваності, **не як поточний стан**.

| Код | Пріоритет | Перевірюваний результат |
| --- | --- | --- |
| **УКР-01** | P0 | Звірити `toṣa` у 1.2 з GRETIL і SARIT; таблиця п'яти чеснот; незалежна рецензія |
| **УКР-02** | P0 | Звірити `āśrama` та `varṇa` у 1.5; редакторське рішення й пояснення |
| **УКР-03** | P0 | Аудит прав перед імпортом; кожен книжковий матеріал має `PROVENANCE.md` |
| **УКР-04** | P1 | Реєстр віршів усіх 20 глав; зіставити GRETIL/SARIT і пропуски |
| **УКР-05** | P1 | Оригінальні примітки до 1.6–1.10 з посиланнями та рецензією |
| **УКР-06** | P1 | Перевірена збірка власного PDF XeLaTeX і артефакт після правового погодження |
| **УКР-07** | P1 | Захист `main`: PR review, CI, заборона force-push, керування Issues |

**Незмінний принцип:** не імпортувати чужі книги, електронні транскрипції або посередні переклади без правової підстави. Машинна перевірка і злитий PR не замінюють рецензування.

## Де перевіряти актуальний стан

- **Незайняті завдання й авторські CLAIM:** [Issues](https://github.com/juv4uk/ukrainian-books/issues), насамперед [права та походження #4](https://github.com/juv4uk/ukrainian-books/issues/4), [захист `main` #8](https://github.com/juv4uk/ukrainian-books/issues/8), [черга незалежних рецензій #109](https://github.com/juv4uk/ukrainian-books/issues/109). Номер Issue — орієнтир, його стан потрібно перевіряти наживо.
- **Що вже пишуть інші агенти:** [відкриті PR](https://github.com/juv4uk/ukrainian-books/pulls) і їхні фактичні diff/CLAIM, а не історична таблиця конфліктів. [Інструмент перетинів файлів](../docs/PR_OVERLAP_GUARD.md) виявляє тотожні шляхи, **але не** різні файли про той самий вірш і не встановлює власника CLAIM.
- **Нумерація санскритського тексту:** [реєстр 20 глав](../research/ashtavakra/registry-20-chapters.md). У двох цифрових свідках звірено по **298 надрукованих номерів**; різниця між 297 `xml:id` на всіх тегах SARIT і 296 `<lg xml:id>` — **дефект обліку розмітки**, не доказ зниклих віршів. Різночитання та право на цифрові файли перевіряються окремо.
- **Формат нових карток:** [технічний контракт `editorial/cards/<глава>.<номер>.json`](../docs/VERSE_CARD_SCHEMA.md), [зведення для незалежного рецензента](../docs/ZVEDENNIA_DLIA_RETSENZENTA.md) і [контроль прогалин](../scripts/check_verse_gaps.py). Існування файлу означає **наявність картки**, не перевірений переклад чи підтверджений науковий статус.
- **Правова й адміністративна готовність:** [реєстр прав](../COPYRIGHT_AND_SOURCES.md), [паспорти джерел](../docs/sources/README.md) та [інструкція реального захисту `main`](../docs/MAIN_PROTECTION_CHECKLIST.md). Зелений аудит захисту не дорівнює активному GitHub ruleset; злиття без необхідного незалежного review не допускається.

### Відтворювана перевірка перед новою роботою

```sh
python3 scripts/check_project.py
python3 scripts/check_duplicate_cards.py --strict
python3 scripts/check_verse_gaps.py
```

Команди виконують структурні перевірки, **не** встановлюють санскритську правильність або правомірність публікації. Відкрийте також [GitHub Actions](https://github.com/juv4uk/ukrainian-books/actions) і порівняйте їхній SHA із поточною гілкою.

| Показник у момент запиту | Значення |
| --- | ---: |
| Відкритих PR | **83** |
| Серед них Draft | **81** |
| JSON-карток в `editorial/cards/` у `main` | **85** |

Це **часовий зріз**, що старіє з наступним комітом, а не дійсний назавжди показник. **85 карток ≠ 85 рецензованих перекладів.** Дати й записи рецензування слід звіряти окремо; сам факт `merged` не є підтвердженням незалежного Review.

Перевіряйте актуальний стан конкретного PR і права на його матеріали, а не висновки з давнього знімка.

## Критерій завершення одиниці роботи

Окремий Issue та точний CLAIM → незалежна гілка → власний внесок із джерелами й походженням → вузький PR → успішні застосовні CI на **актуальному** SHA → **незалежний** технічний або філологічний review → злиття лише за виконання захисту `main`. Якщо рецензента немає, PR лишається на перевірці; зелений CI не є дозволом обійти цю умову.
