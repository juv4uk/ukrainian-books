**Issue:** [УКР-09 / #21](https://github.com/juv4uk/ukrainian-books/issues/21) · **Стан:** технічний контроль, не правова експертиза.

## Джерело канону

- Канонічний файл: [`juv4uk/sens/LICENSE`](https://github.com/juv4uk/sens/blob/main/LICENSE).
- Перевірений Git blob SHA: `a49660652423dcc5352c11456f31bca8806c0d25`.
- Канонічні UTF-8 байти: **649 байтів**.
- Незалежний SHA-256: `395fc9e43412edde4884568d5b0949f1d7c992f6503946746556eb1bb52b9bb0`.

31.10.2026 обидва файли `LICENSE` і `VOLNOST.md` репозиторію `juv4uk/ukrainian-books` мали **точно такий самий вміст**, як `juv4uk/sens/LICENSE`. Ліцензію не редагували й не підміняли, друга ліцензія відсутня.

## Навіщо потрібна окрема перевірка

Поточний `scripts/check_project.py` перевіряє ідентичність `LICENSE` та `VOLNOST.md`, а також заголовок. Дві **однаково змінені** копії пройдуть цю частину перевірки. Новий контроль порівнює кожну копію із заздалегідь перевіреним SHA-256 канонічних байтів; навіть однакове спільне редагування обох файлів не пройде.

## Відтворювана перевірка (без мережі)

```sh
python3 scripts/check_volnost_canon.py
python3 -m unittest discover -s tests -p 'test_volnost_canon.py' -v
python3 scripts/check_project.py
```

Також доступний параметр `--root /шлях/до/репозиторію` для тестового каталогу. Скрипт **тільки читає файли**, не робить мережевих запитів і не записує/не «виправляє» ліцензію. Повертає ненульовий код при помилці та машинозчитуваний JSON-звіт.

[GitHub Actions `volnost-canon.yml`](../.github/workflows/volnost-canon.yml) запускає скрипт, шість модульних тестів і наявну перевірку проєкту на PR, push до `main` або вручну. Звіт CI слід перевіряти саме для актуального SHA.

## Негативні випадки

1. Спільна зміна обох копій при збереженні їхньої рівності.
2. Одностороння зміна однієї копії.
3. Відсутній файл `VOLNOST.md`.
4. Зайвий кінцевий перенос рядка в обох копіях.
5. Відсутність обох файлів.
6. Позитивний приклад — ідентичні канонічні копії.

## Межі гарантії

- Це **технічна перевірка SHA-256**, а не правовий висновок, офіційний SPDX-ідентифікатор чи нова умова ліцензії.
- Незмінний хеш фіксує **вже погоджений текст**. Оновлення канону потребує окремого явно санкціонованого рішення — агент не змінює хеш потайки, щоб приховати редагування.
- Workflow сам по собі **не захищає `main` від обходу**. Для примусової перевірки потрібен GitHub ruleset із вимогою успішного check, забороною force-push і незалежним рев'ю — див. [Issue #8](https://github.com/juv4uk/ukrainian-books/issues/8).
