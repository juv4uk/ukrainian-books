# Перевірка походження (Issue #4, УКР-03)

Це **формальний** шлюз для відкритих книжкових матеріалів, а не юридичний висновок і не підтвердження справжності договору. Усі нові тексти, обкладинки й інші файли книги розміщуються у каталозі `books/<назва>/` з паспортом `PROVENANCE.md`. Використовуйте [чинний шаблон](PROVENANCE_TEMPLATE.md).

## Команди

```sh
python3 -m unittest discover -s tests -p 'test_check_provenance.py' -v
python3 scripts/check_provenance.py --report reports/provenance.json
```

На `push` і `pull_request` працює [новий workflow](../.github/workflows/provenance-audit.yml). Наявні workflow не змінюються.

## Правила блокування

- Каталог лише з чернеткою `PROVENANCE.md` (без жодних книжкових матеріалів) допускається.
- Якщо додано хоч один файл книги, потрібні всі 12 заповнених полів паспорта, статус **«дозволено до публікації»**, HTTPS-посилання на доказ прав, дата перевірки й рецензент.
- Кожен вид використання має окрему позитивну позначку у полі дозволів: `PDF: так; EPUB: так; редагування: так; поширення: так`.
- Заповнювачі `TODO`, `невідомо`, `уточнити` або відсутні поля блокують книжкові файли.

**Обмеження:** будь-хто може написати хибну декларацію. Скрипт не встановлює автора, не перевіряє зовнішні URL і не встановлює дійсності дозволів. Статус `metadata-complete` означає тільки заповнені реквізити. Докази, ліцензії, згода правовласника і рецензування мають перевірятися **людиною**. Не розміщуйте приватні договори чи персональні дані у відкритому GitHub; для конфіденційних підтверджень погоджуйте безпечну процедуру.
