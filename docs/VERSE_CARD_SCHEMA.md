# Контракт редакторської картки «Аштавакра-ґіти»

**Статус:** технічна схема, не текстологічна рецензія. Завдання: [РЕД-01 / Issue #20](https://github.com/juv4uk/ukrainian-books/issues/20).

## Для чого

На кожен вірш передбачена окрема **власна** JSON-картка `editorial/cards/<глава>.<номер>.json`. Нумерація звіряється з наявною [таблицею 20 глав](../research/ashtavakra/registry-20-chapters.csv), де 298 очікуваних позицій. Враховуємо, що цей індекс сам потребує подальшої наукової перевірки — жодне ім'я файлу не є доказом правильності прочитання.

Картки не створюються автоматично з чужого корпусу. [Незаповнений приклад](VERSE_CARD_TEMPLATE.json) — **технічний зразок для 1.1**, який не вважається перевіреним і не є частиною каталогу реальних карток. Залишені `null` означають «не перевірено», а не нульове/відсутнє значення в санскриті.

## Обов'язкові ключі JSON

| Ключ | Зміст |
| --- | --- |
| `schema_version` | Ціле число `1` |
| `id` | Номер `глава.вірш`, наприклад `1.1`; назва файлу має збігатися |
| `work` | Точна назва `Аштавакра-ґіта` |
| `status` | `чернетка`, `перевірено`, `рецензовано` |
| `author` | Автор **українського внеску**; для чернетки може бути `null` |
| `sources.gretil`, `sources.sarit` | Для кожного: перевірюваний `url`, точний `locator`, `checked_on` (`YYYY-MM-DD` або `null`) |
| `sanskrit` і `iast` | Перевірене читання і транслітерація; у чернетці допускається `null`. Тексти конкретних цифрових видань копіювати тільки за правової підстави |
| `grammar` | Власний стислий граматичний аналіз |
| `literal_meaning` | Власне дослівне пояснення, відокремлене від літературного перекладу |
| `ukrainian_translation` | Власний український переклад, не сучасний чужий |
| `commentary` | Самостійний філософський коментар із бібліографічними посиланнями |
| `variants` | Список власних заміток: `witness`, `note`, `evidence_url`. Порожній список **не** означає, що різночитань немає |
| `variants_checked` | `true` лише після фактичного порівняння свідків |
| `rights` | `basis`, `evidence_url`, `verified`, `own_ukrainian_text`; не плутати вільність давнього твору з правами цифрової транскрипції |
| `review` | `reviewer`, `reviewed_on`, `review_url` — документальне підтвердження окремої незалежної рецензії |

## Закрита структура JSON

Для `schema_version=1` дозволені **лише описані ключі** — на верхньому рівні й у вкладених об'єктах. Зайві ключі, зокрема наслідки описок, валідатор відхиляє, щоб редактори не приймали неконтрольованих полів за частину академічного апарату.

- `sources`: лише `gretil` і `sarit`; у кожному — `url`, `locator`, `checked_on`.
- Кожен елемент `variants`: `witness`, `note`, `evidence_url`.
- `rights`: `basis`, `evidence_url`, `verified`, `own_ukrainian_text`.
- `review`: `reviewer`, `reviewed_on`, `review_url`.

Нові типи свідків, допоміжні поля та зміни структури потребують окремої пропозиції, перегляду схеми й версіонування; їх не додають неузгоджено в одну картку. Цей контроль перевіряє структуру, **не** встановлює достовірності тексту, правомірності використання чи незалежності рецензії.

**Виняток нумерації:** SARIT не має окремого XML-ID `verse_18.95`, хоча сам вірш присутній у спільному `<lg xml:id="verse_18.96">`. Для картки 18.95 у SARIT-локаторі використовувати `verse_18.96#18.95`, пояснивши в `variants` або коментарі структуру цифрового тексту. Це *наша* умовна адреса, не нативний ID SARIT.

## Переходи статусу

**Чернетка.** Усі ключі присутні. Порожні дослідницькі поля залишаються `null`, `checked_on: null`; не заповнювати текст вигадками. Посилання на цифрові корпуси не доводить звірення.

**Перевірено.** Обов'язкові заповнені поля від `sanskrit` до `commentary`, ім'я автора, дати звіряння двох корпусів, `variants_checked: true`, власний український текст і позитивний аудит прав із URL доказу. Цей статус означає лише задокументовану **авторську перевірку**; не незалежне наукове схвалення.

**Рецензовано.** Додатково вказано окремого рецензента (не автора), дату та пряме HTTPS-посилання на зафіксовану рецензію. Валідатор перевіряє **наявність полів**, але не може підтвердити реальну незалежність рецензента чи якість висновків. Потрібний людський review у GitHub і перевірка рецензії координатором.

Право на власний український переклад і право на передрук чужого цифрового тексту — різні питання. Жоден статус картки **не знімає** вимоги створити [паспорт походження книги](PROVENANCE_TEMPLATE.md) та пройти [контроль прав](../COPYRIGHT_AND_SOURCES.md) перед публікацією PDF/EPUB.

## Запуск

```sh
python3 scripts/check_project.py
python3 scripts/check_editorial_cards.py
python3 -m unittest discover -s tests -p 'test_editorial_cards.py' -v
```

Скрипт використовує тільки Python стандартної бібліотеки, не робить мережевих запитів. Перевіряє всі `*.json` під `editorial/cards/` (якщо каталог уже є), зокрема дублікати ID і прогалини в заповненні для відповідних статусів. Якщо карток немає, друкує це прямо; **це не звіт про 298 перевірених віршів**. Окремий workflow `editorial-cards.yml` повторює ці команди у GitHub Actions.

## Джерела цифрових свідків

- [GRETIL, Aṣṭāvakragītā](https://www.gretil.uni-goettingen.de/gretil/corpustei/transformations/html/sa_aSTAvakragItA.htm) — електронна транскрипція, не критичне видання.
- [SARIT, Aṣṭāvakragītā](https://github.com/sarit/SARIT-corpus/blob/master/astavakragita.xml) — TEI-транскрипція, не критичне видання.
- [Аудит прав](../COPYRIGHT_AND_SOURCES.md) і [глосарій](../editorial/GLOSSARY.md) — документи редакції.

Ця схема — власний технічний внесок під незміненою «ВОЛЬНІСТЮ». Вона **не** містить текстів чужих перекладів чи коментарів.
