# РЕД-04 — протокол незалежного рецензування внесків

**Статус:** авторська редакційна процедура, запропонована для незалежного технічного й редакторського перегляду в [Issue #142](https://github.com/juv4uk/ukrainian-books/issues/142). Сам документ **не є ухваленим рішенням редакції**, а наявність цього файла не робить жоден переклад рецензованим.

Мета — перевести перевірюваний внесок у перевірюване **людське рішення**. [Схема карток](VERSE_CARD_SCHEMA.md) описує дані; [паспорт походження](PROVENANCE_TEMPLATE.md) описує книгу; [правила внесків](../CONTRIBUTING.md) установлюють передумови злиття. [РЕД-03](https://github.com/juv4uk/ukrainian-books/issues/109) окремо автоматизує **спостереження** за чергою PR; цей документ не дублює його код, не запускає workflow і не схвалює PR автоматично.

## 1. Хто може рецензувати

1. **Автор внеску** відповідає за точні джерела, відтворювані перевірки, самокритику й виправлення. Автор може провести повторну **авторську** перевірку, але не може надати самому собі незалежне схвалення.
2. **Санскритолог / текстолог** незалежно перевіряє форми, синтаксис, сандгі, межі джерел і статус різночитань. Потрібний для перекладів, IAST, граматики, атрибуцій мовця, висновків про варіанти.
3. **Український редактор** незалежно перевіряє природність і точність української редакції, сталість термінів та відокремлення перекладу від тлумачення.
4. **Аудитор прав** перевіряє походження, заявлене авторство й юридичні підстави використання конкретних матеріалів. Де потрібен професійний юридичний висновок або дозвіл правовласника — ставить блокер, а не здогад.
5. **Технічний рецензент** перевіряє код, тести, безпеку CI, відтворюваність, архітектуру та вплив на інші PR. Потрібний для інструментів, workflow, даних схеми та збірки книг.

Одна компетентна **незалежна** людина може обґрунтовано перевірити кілька ділянок, але в звіті потрібно окремо вказати, **яку саме** й на чому ґрунтується висновок. Не записувати роль, ім'я, рецензію або «APPROVE», яких немає. Важлива реальна незалежність від авторства й власного внеску, не просто інший GitHub-акаунт; можливі конфлікти інтересів повідомляють у звіті. **Робота декількох агентів через один власницький обліковий запис — не автоматично незалежне рецензування.**

## 2. Обов'язковий пакет доказів

Перед незалежною рецензією автор надає в PR: посилання на Issue і CLAIM, точний head commit SHA, список змінених файлів, тип внеску, точні джерела й локатори, перелік неперевірених тверджень, правовий статус кожного фрагмента, результати **дійсно виконаних** тестів (успіх / відмова / не запускалося). Якщо за час рецензії змінюється head SHA чи суттєвий diff, попередній висновок слід явно перевірити на актуальність; за потреби повторити review та CI.

Для текстової картки зафіксувати:
- **Точні незалежно перевірені електронні посилання**, наприклад GRETIL `Avg_1.2` і SARIT `verse_1.2`. Поле `checked_on` — дата звірки, **не** знак незалежного наукового схвалення.
- **Оригінал і передача:** чи є джерело давнім текстом, сучасним друкованим виданням, електронною транскрипцією, дзеркалом або власним перекладом. Знімок дзеркала не доводить тотожності поточному GRETIL; дві цифрові копії не доводять двох незалежних рукописів.
- **Граматику й лексеми:** як доведені морфологічні форми, сандгі, значення, невизначені альтернативи і зв'язок дослівної версії з українським текстом.
- **Варіанти:** окремо (а) графічна передача, пробіли, авґраха; (б) відмінність букв / слів; (в) заголовок мовця або метадані; (г) можливе рукописне різночитання **лише з доказом рукописного чи критичного апарату**. Наприклад `tyāgaparo 'vratī` і `tyāgaparo+avratī` не оголошують різними рукописними читаннями тільки через знак сандгі.
- **Коментар:** чи відрізняється філософське тлумачення автора від встановленого буквального тексту; чи зазначені джерела традиційного й сучасного коментаря, якщо автор на них посилається.

## 3. Правовий перегляд не замінюється філологією

Перевіряти окремо: (1) права на давній оригінальний твір; (2) права й умови **конкретної** цифрової транскрипції та редакторського апарату; (3) права на сучасний чужий переклад і коментар; (4) права на **наш** український внесок. Посилання чи бібліографічний опис самі по собі не є дозволом на передрук. У сумніві **не** вставляти повну охоронювану транскрипцію та позначати `rights.verified=false`.

Для книги, PDF або EPUB обов'язковий окремий `books/<назва>/PROVENANCE.md` із перевіреною підставою дозволених способів публікації; рецензований вірш не дає автоматичного дозволу на його видання у складі книги. **«ВОЛЬНІСТЬ»** стосується лише власних внесків, не переліцензовує сторонніх матеріалів. `LICENSE` і `VOLNOST.md` не змінювати. Якщо правовий висновок або дозвіл відсутній — цей блокер залишається відкритим навіть після успішного CI.

## 4. Рішення за типом внеску

| Внесок | Мінімальний незалежний огляд | Чого не доводить CI |
| --- | --- | --- |
| Санскрит / українська картка | Текстологічна / санскритологічна й українська редакційна оцінка; права на включений матеріал | Значення слова, переклад, незалежність джерел |
| Наукова бібліографія / історія видань | Звірка атрибуції, DOI/видання, межі цитування, прав | Існування або коректність інтерпретації праці |
| Python, CI, схема, автоматичний звіт | Незалежний технічний перегляд логіки, безпеки, позитивних і негативних тестів | Відсутність прихованого ризику чи академічну якість |
| Книга, PDF, EPUB | Редакторський і технічний перегляд, паспорт походження та **окреме** правове погодження | Дозвіл на публікацію тексту, малюнків, шрифтів |

Рецензент залишає **одне конкретне** рішення через GitHub Review: `COMMENT` — спостереження без схвалення; `REQUEST_CHANGES` — блокер із відтворюваними заувагами; `APPROVE` — позитивна оцінка **визначеного обсягу та SHA**. `APPROVE` не замінює право власника визначити канонічний формат, не підтверджує ліцензійне право і не є сам по собі дозволом на злиття. Точний звіт можна оформити за [шаблоном](INDEPENDENT_REVIEW_TEMPLATE.md).

## 5. Статуси картки й злиття PR

- **`чернетка`**: наявність тексту, картки чи зеленого CI не є завершеним review. Невідомі поля лишаються `null`; невирішені твердження — явними.
- **`перевірено`** за схемою — підтверджена **авторська** перевірка з обов'язковими джерелами, автором і позитивним доказом прав. Це **не** автоматично «незалежно рецензовано».
- **`рецензовано`**: документовано незалежного від автора компетентного рецензента, дату, доказовий HTTPS-URL до фактичного review та позитивний розгляд потрібних для цього внеску аспектів. Координатор звіряє реальність рішення, а не тільки JSON-поля.
- **Злиття PR**: тільки після актуального `main`, відсутності конфліктів із чужими CLAIM, зелених обов'язкових CI, перевірки прав і **справжнього незалежного погодження**. Технічна mergeability, відсутність GitHub branch protection або зелені workflow не знімають цих вимог.

Якщо автор не може здобути незалежну рецензію — PR залишається Draft із записаним блокером; не змінювати статус заради кількості злиттів. Не можна самостійно знімати чужий CLAIM, підробляти рев'ю, перезаписувати `main` через force-push або обходити перевірки.

## 6. Застосування до незавершеної черги

Для кожного відкритого Draft PR координатор перевіряє **конкретні** head SHA, diff, CLAIM, CI, відсутні рецензії та правові питання. Далі має бути один прозорий маршрут: (а) автор доопрацьовує; (б) реальний незалежний фахівець рецензує; (в) автор добровільно закриває дубль після збереження корисних фактів, без видалення чужої роботи. Не позначати всі Draft як неякісні й не підміняти зміни статусу автоматичним звітом.

**Це пропозиція редакційного процесу, а не юридична консультація, дозвіл на використання цифрових корпусів, критичне видання чи рецензія вже відкритих PR.**
