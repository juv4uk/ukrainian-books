# Контроль хронології редакторських карток

**Завдання:** [РЕД-08 / Issue #222](https://github.com/juv4uk/ukrainian-books/issues/222).

## Причина

У схемі картки перевіряється написання дати, але запис на кшталт
`review.reviewed_on: "2099-01-01"` технічно має правильний формат, хоча
не може підтверджувати вже проведену рецензію. Аналогічний ризик мають
`sources.gretil.checked_on` і `sources.sarit.checked_on`.

Новий перевіряльник відхиляє майбутні дати у **трьох** названих полях;
орієнтир — поточний календарний день **UTC**, зафіксований на початку запуску.
Дату поточного дня та попередні дати допускає. `null` і відсутні поля
не підмінює вигаданими підтвердженнями: повноту структури перевіряє
`scripts/check_editorial_cards.py`.

## Відтворення

```sh
python3 scripts/check_project.py
python3 scripts/check_editorial_cards.py
python3 scripts/check_card_chronology.py
python3 -m unittest discover -s tests -p 'test_card_chronology.py' -v
```

Workflow `.github/workflows/card-chronology.yml` запускає нову перевірку
і синтетичні тести для PR та `main`. Unit-тести передають фіксовану
дату `2026-10-31`, щоб не залежати від часу запуску; реальний workflow
використовує дату UTC свого runner. Скрипт не звертається до мережі.

## Межі машинного контролю

**Схвалення CI не означає незалежної філологічної, правової чи редакторської
рецензії.** Минулу дату можна вказати без фактичного відвідування джерела,
а URL рецензії — без справжнього незалежного експерта. Перед підвищенням
статусу картки відповідальний редактор має перевірити докази та особу
рецензента окремо.

Ліцензійні тексти `LICENSE` та `VOLNOST.md` не змінюються.
