# УКР-07: ретроспективний аудит GitHub Reviews злитих PR

Пов'язано з [Issue #288](https://github.com/juv4uk/ukrainian-books/issues/288) та основною адміністративною задачею [#8](https://github.com/juv4uk/ukrainian-books/issues/8).

## Навіщо

GitHub Actions може бути зеленим, навіть коли вже злитий PR **не має видимого GitHub APPROVED іншого акаунта**. Наприклад, PR #162 було злито 31.10.2026 комітом 4febc6a8cacd82915e6447bc692ed78810daa3b3, але GitHub Reviews на момент первинного аудиту були порожні. Потрібен перевірюваний історичний звіт, а не вигадане рецензування.

Цей засіб **не встановлює правила захисту** й не дає дозволу на злиття. Він лише аналізує дані GitHub, видимі під час запиту. Нуль GitHub Reviews не означає, що не було жодної консультації поза GitHub.

## Що вважаємо спостереженим GitHub-схваленням

Лише запис APPROVED з усіма ознаками:

- автор рецензії має інший GitHub login, ніж автор PR;
- дата подання рецензії не пізніше часу злиття;
- commit_id рецензії точно дорівнює head SHA злитого PR;
- це останнє до злиття вирішальне рішення відповідного акаунта: CHANGES_REQUESTED і DISMISSED скасовують раніше подане схвалення; COMMENTED не змінює рішення.

**Важлива межа:** навіть два різні GitHub-акаунти не доводять незалежності двох людей, фаховості або правомірності перевірки. Скрипт повідомляє лише github_approval_observed. Усі неоднозначні й неповні дані залишаються insufficient_data, а не автоматичним звинуваченням.

## Запуск

У корені репозиторію:

    python3 -m unittest discover -s tests -p 'test_merged_reviews.py' -v
    python3 scripts/audit_merged_reviews.py --fixture шлях/до/синтетичного-знімка.json
    GITHUB_TOKEN=... python3 scripts/audit_merged_reviews.py --repo juv4uk/ukrainian-books --limit 25

Формат синтетичного знімка: об'єкт JSON із полями pulls (список відповідей GitHub Pull Requests) і reviews (словник, де номер PR у вигляді рядка вказує на список GitHub Reviews). Відсутній ключ reviews для PR означає **не отримано даних**, а не порожній список рецензій.

Живий режим використовує тільки GitHub REST GET, фіксований домен api.github.com, обмежену пагінацію, без зміни PR. Токен може передаватися через GITHUB_TOKEN або GH_TOKEN, ніколи не друкується у звіт. Помилка API/JSON робить запуск неуспішним; відсутність історичних рецензій повертає звіт із попередженнями, **не червоний CI сьогоднішнього PR**.

Окремий workflow «УКР-07 — ретроспективні GitHub Reviews» на push/PR запускає лише **офлайн-синтетичні тести** без мережевих запитів і токенів для зовнішніх PR. Ручний workflow_dispatch після тестів робить read-only звіт за останніми 25 злитими PR. Це не незалежний технічний Review і не заміна адміністраторського захисту main.

## Ліцензія і джерела

Код, документація та синтетичні тести — наші власні внески за незмінною «ВОЛЬНІСТЮ». Санскритські корпуси, книжки, PDF, чужі переклади або матеріали третьої сторони не переносяться. Інструмент читає лише метадані GitHub Reviews і PR.
