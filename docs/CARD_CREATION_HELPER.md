# Створення порожньої редакторської картки

Інженерний допоміжний інструмент до [схеми](VERSE_CARD_SCHEMA.md) та [шаблону](VERSE_CARD_TEMPLATE.json). Він **не перекладає**, не виконує звірки GRETIL/SARIT, не підтверджує права й не створює доказ незалежної рецензії.

Спочатку перевірте відкриті задачі, PR і CLAIM. Лише для **вільного** номера вірша виконайте з кореня репозиторію:

    python3 scripts/create_verse_card.py 1.1 --preview
    python3 scripts/create_verse_card.py 1.1
    python3 scripts/check_editorial_cards.py
    python3 scripts/check_duplicate_cards.py --strict
    python3 scripts/check_project.py

Перша команда тільки виводить майбутній JSON. Друга створює картку за адресою «editorial/cards/1.1.json» **лише коли його не існує**: жоден наявний файл не перезаписується. Номер береться зі стовпця GRETIL_віршів локального [реєстру](../research/ashtavakra/registry-20-chapters.csv), а не з кількості XML-ID у SARIT. Тому 18.95 не губиться через злиту розмітку SARIT: використовується умовний локатор «verse_18.96#18.95», описаний у схемі. Це не нативний XML-ID.

Генератор копіює з незаповненого локального шаблону лише структуру і наявні URL свідків. Дата звірки, санскрит, IAST, граматика, переклад, коментар, права й рецензія **не заповнюються**. Усі нові картки мають статус «чернетка», variants_checked: false, rights.verified: false. Висновки на основі джерел додає автор вручну, після перевірки умов цитування; статус «перевірено» чи «рецензовано» генератор не встановлює.

Негативні тести:

    python3 -m unittest discover -s tests -p 'test_create_verse_card.py' -v

Вони покривають обмеження нумерації, 18.95, відмову перезаписувати файл, перегляд без запису, небезпечні заповнені поля шаблону й символьне посилання каталогу. **Це автоматизація підготовки чернетки, а не науковий результат чи дозвіл на публікацію.**
