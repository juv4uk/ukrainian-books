# Українська бібліотека — власні переклади та дослідження

Незалежний український корпус філологічних досліджень, редакторських карток, власних перекладів, бібліографії та інструментів перевірки. Перший напрям — **«Аштавакра-ґіта»**. Це **не форк** [історичного сховища livros](https://github.com/juv4uk/livros): чужі книжки, PDF, переклади та коментарі без підтверджених прав сюди не переносимо.

**Як читати статуси:** електронна транскрипція санскриту — це свідок тексту, а не автоматично критичне видання; власна редакторська картка — чернетка до незалежної рецензії; сучасне філософське есе — не традиційний коментар і не доказ авторського задуму давнього твору.

## «Аштавакра-ґіта»: джерела та нумерація

- [Реєстр 20 глав](research/ashtavakra/registry-20-chapters.md) і [порозділовий CSV](research/ashtavakra/registry-20-chapters.csv) — машинна звірка двох цифрових свідків: [GRETIL](https://gretil.sub.uni-goettingen.de/gretil/corpustei/transformations/plaintext/sa_aSTAvakragItA.txt) та [SARIT TEI](https://github.com/sarit/SARIT-corpus/blob/master/astavakragita.xml).
- За методом, описаним у реєстрі, **обидва свідки містять по 298 пронумерованих текстових позицій у 20 главах**, без розбіжностей у наборі надрукованих номерів. Водночас SARIT має 297 атрибутів `xml:id="verse_N.M"` на різних XML-тегах і 296 таких атрибутів саме на `<lg>`. **Це різні одиниці підрахунку, а не два відсутні санскритські вірші.** Історичний стовпець `SARIT_віршів` у CSV обліковує лише `<lg xml:id>`, що пояснено в реєстрі.
- [Карта різночитань](research/ashtavakra/variant-map.md), [відбір кандидатів для ручного розбору](research/ashtavakra/variant-shortlist.md) і [часткова перевірка третього цифрового свідка](research/ashtavakra/third-witness.md) — окремі етапи дослідження. Нумераційний збіг **не доводить** тотожності санскритських читань.
- [285 чи 298 шлок?](research/ashtavakra/studies/verse-count-285-vs-298.md) — методологічна джерелознавча чернетка щодо різних підрахунків; без припущення про невстановлене критичне видання.

Для незалежного відтворення звірки треба врахувати викладені в реєстрі **версії й походження цифрових файлів**, зокрема обмеження доступу до живого GRETIL. Це не академічне засвідчення всіх різночитань.

До використання джерел і випуску книжки перевіряйте [реєстр прав](COPYRIGHT_AND_SOURCES.md), [паспорти джерел](docs/sources/README.md) та [шаблон паспорта походження окремого видання](docs/PROVENANCE_TEMPLATE.md). Бібліографічне посилання не замінює дозволу на відтворення чужого тексту. Навіть успішна тестова збірка PDF не є дозволом на публікацію; PDF/EPUB для конкретної книжки потребують окремої перевірки прав і походження.

## Як долучитися та перевірити

Перед правками перегляньте [дорожню карту](tasks/ROADMAP.md), [правила співпраці](CONTRIBUTING.md) та [інструкцію початку роботи](docs/START.md). Оберіть незайнятий Issue, залиште точний **CLAIM**, працюйте в окремій гілці й відкривайте вузький PR. Перед злиттям потрібні актуальний SHA `main`, зелені перевірки й незалежний відповідний review.

```sh
python3 scripts/check_project.py
python3 scripts/check_duplicate_cards.py --strict
python3 scripts/bootstrap_issues.py --dry-run
```

Workflow «Якість і походження» запускається на PR і push до `main`; робочий процес складання власних видань запускається окремо. **Автоматичний тест контролює структуру, а не істинність перекладу чи правовий статус джерела.**
